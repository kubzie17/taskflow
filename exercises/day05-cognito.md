# Optional extension · Swap the identity provider

Start only once the local acceptance checks pass and an approved training pool, time, owner and cleanup route are available. Keep the API on your laptop. The cloud service supplies identities. Your local FastAPI server still decides whether a reader or dispatcher can create a booking. Allow 35–50 minutes in a follow-on session. A trainer-owned demonstration works if learner write permissions are restricted.

## Set up an approved pool or use the trainer's

1. In the approved region open **Amazon Cognito → User pools**. Inspect the designated lab pool first. If you are expressly allowed to create a disposable pool, use a fictional name, direct username sign-in, admin-created accounts, no SMS, no paid threat protection, no external email sending and no optional MFA or external federation for this disposable lab. Keep required attributes minimal. Use an approved Lite or Essentials configuration compatible with the chosen hosted interface. Keep the approved account and region unchanged.
2. Select or create a **public client without a secret**. In the client login settings enable the Cognito user pool identity provider, **authorisation code grant** and **openid** scope. Set the callback exactly to `http://localhost:8765/callback`. Keep client credentials and implicit grants off. Add a standard, available Cognito prefix domain for managed login or the hosted UI. A client that has a secret is unsuitable for this example.
3. In **Groups** create `taskflow-reader` and `taskflow-dispatcher`. In **Users** create two fictional, admin-provisioned users, choose no invitation delivery, handle any first-login password change privately, and put each in its own group. If the pool requires personal contact details or paid messaging, use the local route. The exercises use a single pilot team. Never assign AWS IAM users to contractors.
4. Copy privately the standard HTTPS **user pool issuer**, public **app client ID**, and HTTPS **hosted domain**. The issuer looks like `https://cognito-idp.REGION.amazonaws.com/POOL_ID`. Open `ISSUER/.well-known/openid-configuration` and the `jwks_uri` it publishes. Verify the issuer and public-key endpoint belong to your pool. The hosted login domain is a different URL. Use `https://taskflow.example.invalid` as the lab resource identifier. Cognito copies the requested resource URL into the access-token audience. It is a label for your local API and is never opened as a website.
5. In an activated PowerShell terminal install the optional RSA dependency and set these variables using your pool's actual values. On macOS/Linux use `export NAME='value'` for each setting. Keep these settings outside Git. Both terminals need the four settings, so reuse the same terminal environment or set them in each. Stop the local issuer process on port 8055 before starting the alternate factory.

```powershell
python -m pip install "PyJWT[crypto]==2.15.1"
$env:TF_COGNITO_ISSUER = 'https://cognito-idp.REGION.amazonaws.com/POOL_ID'
$env:TF_COGNITO_CLIENT = 'YOUR_PUBLIC_CLIENT_ID'
$env:TF_COGNITO_DOMAIN = 'https://YOUR_PREFIX.auth.REGION.amazoncognito.com'
$env:TF_COGNITO_RESOURCE = 'https://taskflow.example.invalid'
python -m uvicorn exercises.day05_cognito:create_cloud --factory --host 127.0.0.1 --port 8055
```

6. From the second terminal run `python -m exercises.day05_pkce`. Your browser opens the provider’s sign-in page. Use the fictional reader. A loopback callback checks the random state and the helper exchanges its one-time code with the original verifier. It sends only the access token to the local API, runs a GET and a fictional POST and prints just their HTTP statuses. Sign out of the hosted session or switch browser profile for the second fictional user and repeat. The dispatcher run intentionally creates one fictional row in `data/day05-lab.db`.
7. **Acceptance.** Reader GET/POST → 200/403. Dispatcher → 200/201. Direct unsigned POST → 401. Only the dispatcher adds a row. Check SQLite before and after. There is no local `/session` login in the cloud factory. A wrong pool, wrong app client, ID token, expired token, unknown key or wrong/missing resource audience must not grant access. If access is denied, capture the first sanitised error and return to the local checks. Never paste a token into a public decoder, Teams or a commit.
8. Stop both local processes. The owner removes only resources created for this lab. In a disposable pool remove its hosted domain, remove deletion protection if enabled and authorised, then delete the pool and verify absence. In a shared pool remove only your own test users, groups, client or domain as agreed with the owner. Confirm cleanup and billing in the same account and region. Keep the private proof to statuses and row deltas.

**What to explain.** OAuth 2.0 provides delegated/limited access. OpenID Connect adds identity information for the client. The ID token is for the client. This helper discards it. A client that uses it for its own login must validate it according to OIDC, including any nonce it sent. The TaskFlow resource server verifies an access token against the configured public keys, RS256, issuer, expiry, token purpose, issuing app client and the requested API audience before mapping its signed groups. Standard Cognito access tokens can omit `aud` without resource binding. This exercise deliberately requests a resource and requires that claim. The local issuer uses an entirely separate signing key and a fixed local audience.

**Technical scope.** This pack includes a provider adapter and PKCE client, plus private offline contract tests. Live hosted login, sandbox permissions, group propagation, pricing tier and cleanup need to be observed in the chosen account.
